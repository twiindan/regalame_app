## Binding constraints (design-contract validator notes)

These are hard constraints on the implementation — treat them as part of each task's acceptance:

1. **Singular table names**: `editorial_decision` / class `EditorialDecision`; `editorial_gate_state` / class `EditorialGateState`. Do not use plural `__tablename__`.
2. **Use the EXPANDED `classify_product` signature** from `design.md` "Interfaces / Contracts":
   `classify_product(item, *, transport=None, timeout=30.0, max_attempts=2, base_url=None, model=None, api_key=None) -> ClassificationResult | None` — not the shorter snippet in the architecture discussion.
3. **`enforce` precondition is explicit**: the effective mode is `enforce` only when `gate_passed is True` AND `coverage_ratio == 1.0` AND `policy_version == EDITORIAL_POLICY_VERSION` AND the configured mode is `enforce`. The design's `effective_filter_mode` snippet omits the `coverage_ratio == 1.0` clause; task 2.6 adds it explicitly.
4. **Provider API-key env var is `EDITORIAL_PROVIDER_API_KEY`**, used consistently everywhere (adapter, job, docs). Base URL `EDITORIAL_PROVIDER_BASE_URL` (default `https://api.nan.builders/v1`), model `EDITORIAL_PROVIDER_MODEL` (default `qwen3.6`).
5. **v1 `EDITORIAL_CONTEXTS` default** = the product's own `category_slug` (matching an existing `/ideas/{slug}` route; zero new routes). Product decision needing sign-off, does not block tasks (see 2.4).
6. **Migration** `down_revision = "9f1c7b2a4d3e"`; naive-UTC datetimes via `utcnow_naive`; strictly additive (only `create_table` + indexes).
7. **Shadow `off` is the default** and must not silently change existing behavior. Existing 128 tests must stay green without semantic modification.

## Product decisions requiring sign-off (do not block tasks)

- **v1 contextual vocabulary** (constraint 5): contexts are limited to the product's own `category_slug`. Widening to a curated superset (`bebe`, `mascotas`, …) is a `EDITORIAL_POLICY_VERSION` bump + spec update.
- **Provider claims** (strict `json_schema`, rate, latency): unresolved empirically by the gate; if `response_format` is rejected, the documented fallback is a policy-version bump, decided then.
